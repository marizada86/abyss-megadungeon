# Explicit activation

Read the project's AGENTS.md first, then the local methodology instructions. Preserve stricter local gates; surface conflicts. Read .atena/add.yaml, relevant canon/spec/evidence and the state bound to this chat under .atena/state/conversations/<key>/plan.yaml before work; legacy .atena/state/plan.yaml is readable but is not a global sequencing lock. Installation neither approves implementation nor installs agents.

The exact phrases in [registry](phrases.json) describe intent. The CLI phrase command only performs whole-input lookup (case-insensitive, NFC, trim); it does not operate an AI client. Quoted phrases, snippets, code, questions about a phrase and mentions inside other prose are not activation requests. The assistant must interpret actual intent, including when UI context quotes a user's message.

“Ativar Atena no projeto”: inspect and prepare adoption; show scope, preserve existing instructions/state/canon and obtain applicable approval before writing. For a new game offer discovery and confirm before starting it.
“Atena, elabore um plano com suas recomendações”: Guided ADD; evidence, recommendations, bounded spec/plan, zero BLOCKING gaps, approval mode and checkpoint before execution.
“Atena, me entreviste”: adaptive discovery in short rounds, using previous answers; record DRAFT decisions and pending gaps, no automatic implementation or promotion.

"Atena, atualize-se para a versão mais recente" and "Atena, se atualize" (with or without a final period): same guarded update-methodology flow. Read [update procedure](UPDATING.md): verify adopted/source versions, compare compatibility and local adaptations, present impacts, honor approvals, preserve canon/knowledge/state/local instructions, back up, validate and report. A phrase match grants no authorization. No configured source means the latest version is unknown.
